## 一、核心答案与适用前提

针对“**两个屏幕同时看同一内容，流量是否只算一份：需要观察哪条路径？**”，家庭网络治理的严酷公理是：**屏幕数量的增加不是线性加法，而是容量消耗的几何级乘法。当客厅电视播放 4K、卧室平板播放 1080p、手机同时刷社交短视频时，多端并发不仅瞬间吞噬百兆下行带宽，更会在全月产生数倍于单人环境的额度穿透风险。**

多屏并发三大核算定理：
1. **并发总带宽叠加公式**：
   $$R_{\text{multiscreen}} = \sum_{i=1}^N R_i = R_{\text{TV}} + R_{\text{Tablet}} + R_{\text{Phone}}$$
   - 客厅 4K (18Mbps) + 卧室 1080p (6Mbps) + 书房办公 (2Mbps) = **峰值需求 26 Mbps**。
2. **月度额度复合累加原理**：家庭月度需求是所有成员独立观影计划的代数和，必须在账本中设立“设备子账户”分别对账。
3. **服务商并发设备数限制 (Device Limit)**：多屏同步观看受限于服务商的账号在线 IP 限制，若超出限制会导致某台设备被强制踢下线。

## 四、核心推导步骤与典型算例

### 算例：三口之家周末晚间多屏并发的真实消耗推导
某三口之家在周六晚间 20:00 至 23:00（黄金 3 小时）的网络行为如下：
- **设备 A（客厅 75寸 4K 电视）**：父母观看海外 4K 超高清电影，平均码率 $16.0\text{ Mbps}$；
- **设备 B（卧室 iPad）**：孩子观看 1080p 动画剧集，平均码率 $5.0\text{ Mbps}$；
- **设备 C（书房笔记本）**：另一家庭成员处理工作并收听海外流媒体音乐，平均码率 $1.5\text{ Mbps}$。
- 全家共用一个 $200.0\text{ GB/月}$ 的月付套餐，连接某标准 $1.0\text{x}$ 节点。

**多屏并发推导精算过程**：
1. **合并瞬时总吞吐速率**：
   $$R_{\text{family}} = 16.0 + 5.0 + 1.5 = 22.5\text{ Mbps}$$
2. **计算 3 小时并发产生的物理流量**：
   $$V_{\text{evening}} = \frac{22.5 \times 10^6 \times 3600 \times 3}{8 \times 10^9} = \frac{243,000 \times 10^6}{8 \times 10^9} = 30.375\text{ GB}$$
3. **账户结算冲击分析**：
   - 仅仅在周六晚间这短短 **3 小时** 内；
   - 整个家庭直接消耗了整整 **$30.375\text{ GB}$** 额度；
   - 占全月 $200\text{ GB}$ 配额的 **$15.19\%$**！
   - 若每个周六日均按此负荷运行（全月 8 天周末），仅周末就将消耗：
     $$8 \times 30.375 = 243.0\text{ GB}$$
   - 套餐在月末前十天就会彻底断流崩塌！
4. **治理优化推导**：
   - 治理动作一：将电视与平板切换至主站推荐的专用 [0.5x 经济流媒体] 节点；
   - 3 小时后台实际扣量骤降至：
     $$Q_{\text{optimized}} = 30.375 \times 0.5 \approx 15.19\text{ GB}$$
   - 全月额度利用率回归至安全绿区，家庭多屏娱乐得以平稳维持。

## 五、底层网络机制与边界案例

### 1. 软路由（OpenWrt）透明代理下的“单 IP 伪装”
若家庭中有多台设备，但服务商套餐严格限制“最多 2 台设备在线”：
- **工程破局方案**：在家庭主路由器上部署透明代理（如 Clash Verge 旁路由或 OpenWrt PassWall）。
- **底层机制**：所有家庭电视、手机、平板在局域网内发出请求，经由软路由的 NAT 转发与代理客户端统一封装。在服务商服务器看来，整栋房屋的所有流量均来自该软路由这单一公网客户端，逻辑上**仅占用 1 个设备名额**，完美解决多屏并发鉴权冲突。

### 2. 局域网 Wi-Fi 5/6 空口竞争（Airtime Fairness）
当电视以 4K 高码率持续拉取时，如果使用的是老旧的 Wi-Fi 5 单频路由器，电视会长时间占用无线信道空口时间（Airtime）。这会导致卧室的平板与手机遭遇严重的无线排队延迟与丢包，引发平板端播放器频繁发生画质降级。多屏并发环境必须搭配支持 Wi-Fi 6 OFDMA 技术的现代路由器。
